# 데일리 자동화 가이드

매일 하는 웹 업무(대시보드 수치 확인, 게시판 새 글 확인, 리포트 내려받기)를 Claude 없이
크롬 혼자 돌리고, 아침에 Claude 가 결과만 정리하게 만드는 방법입니다.

핵심은 도구 하나입니다. `chrome_shortcut` 에 작업을 저장하고, 거기에 시각을 붙이고,
다음 날 아침에 이력을 읽습니다.

## 왜 크롬 안에서 도는가

Claude Code 를 켜야만 돌아가는 자동화는 자동화가 아닙니다. MCP 브리지는 Claude Code 가
띄우는 프로세스라 Claude 가 없으면 같이 없습니다. 항상 켜져 있는 것은 크롬뿐이라,
예약 실행은 크롬 확장 안에서 돕니다. OS 작업 스케줄러나 headless 브라우저를 쓰지 않는
이유도 같습니다. 로그인 쿠키와 확장, 사용자 탭 보호 규칙이 전부 여러분의 크롬 프로필
안에 있어서, 밖에서 돌리면 셋 다 처음부터 다시 만들어야 합니다.

## 1단계: 로그인은 손으로 한 번만

**비밀번호는 저장하지 않습니다.** 확장 저장소에 넣는 순간 같은 프로필의 다른 확장,
개발자 도구, 디스크 복사본에 평문으로 노출됩니다. 확장이 암호화해도 열쇠가 같은 곳에
있으니 눈속임입니다. 그래서 아예 선택지를 만들지 않았습니다.

대신 **크롬 프로필의 로그인 세션(쿠키)** 을 그대로 씁니다. 자동화할 사이트에 평소처럼
크롬에서 한 번 로그인해 두면, 예약 실행이 여는 작업 탭도 같은 프로필이라 그 세션을
공유합니다. 그래서 저장하는 작업은 로그인 화면을 거치지 않고 목적지 URL 로 바로
이동합니다.

세션이 만료되면 어떻게 아느냐는 4단계에서 다룹니다.

## 2단계: 할 일을 shortcut 으로 저장

`chrome_shortcut` 의 `save` 로 단계 목록을 이름 붙여 저장합니다. 예약할 작업은
**첫 단계가 반드시 `chrome_navigate`** 여야 합니다. 예약 실행은 작업 탭이 없는 상태에서
시작하므로, 탭을 만드는 길이 navigate 하나뿐입니다.

```json
{
  "action": "save",
  "name": "board-watch",
  "return": ["latest"],
  "params": { "lastSeen": { "required": true, "description": "마지막으로 본 글 번호" } },
  "steps": [
    { "tool": "chrome_navigate", "args": { "url": "https://board.example.com/list" } },
    {
      "tool": "chrome_extract",
      "as": "latest",
      "args": {
        "fields": {
          "id": { "selector": ".row:first-child .id" },
          "title": { "selector": ".row:first-child .title" }
        }
      },
      "stopIf": { "path": "latest.values.id", "op": "eq", "value": "{{params.lastSeen}}" }
    }
  ]
}
```

`return` 에 적은 이름만 이력에 남습니다. 예약 실행에는 값을 요청할 사람이 없으니
저장할 때 정해 둬야 합니다.

`stopIf` 는 "새 글이 없으면 여기서 끝" 이라는 뜻입니다. 정상 종료이므로 실패로
기록되지 않고 알림도 오지 않습니다.

## 3단계: 시각을 붙인다

```json
{
  "action": "schedule",
  "name": "board-watch",
  "schedule": { "every": "1h" },
  "params": { "lastSeen": "10422" }
}
```

표현은 둘 중 하나입니다.

| 표현                                                              | 뜻                       |
| ----------------------------------------------------------------- | ------------------------ |
| `{ "every": "15m" }` (또는 `1h`, `6h`, `24h`)                     | N 시간(분)마다           |
| `{ "daily": ["08:00"] }`                                          | 매일 그 시각 (로컬 시간) |
| `{ "daily": ["08:00"], "days": ["mon","tue","wed","thu","fri"] }` | 평일 그 시각             |

`daily` 는 최대 4개이고 같은 날 안에서 5분 이상 떨어져 있어야 합니다. cron 표기는 쓰지
않습니다. 읽기 어렵고, 분 단위 표현력이 데일리 업무에 필요 없습니다.

예약 옵션은 셋입니다.

- `notify` (기본 켜짐): 실패하면 크롬 알림을 한 줄 띄웁니다.
- `report` (기본 꺼짐): 실행 결과를 다운로드 폴더에도 JSON 으로 남깁니다.
- `loginCheck`: 4단계 참조.

예약을 걸면 검증이 **그 자리에서** 끝납니다. 파라미터 오타, 저장된 탭 번호, 첫 단계
규칙 위반은 전부 지금 거절됩니다. 새벽 3시에 실패하는 것보다 지금 실패하는 편이 낫기
때문입니다.

## 4단계: 로그인 만료를 알아채게 만든다

세션이 끊기면 사이트가 로그인 화면을 보여 주고, 그대로 두면 매일 빈 결과가 쌓입니다.
로그인 화면인지 판정하는 단계를 하나 넣고, 그 단계 이름을 `loginCheck` 로 지목하면
그 중단은 "실패" 가 아니라 `login_required` 로 기록되고 알림이 옵니다.

```json
{
  "tool": "chrome_find",
  "as": "loginForm",
  "args": { "query": "비밀번호 입력창", "maxResults": 1 },
  "stopIf": { "path": "loginForm.matches", "op": "notEmpty" }
}
```

```json
{
  "action": "schedule",
  "name": "crm-export",
  "schedule": { "daily": ["07:30", "12:30"] },
  "loginCheck": "loginForm"
}
```

알림이 오면 크롬에서 그 사이트에 다시 로그인만 하면 됩니다. 다음 회차부터 정상입니다.

## 5단계: 아침에 Claude 가 하는 일

Claude 에게 "밤새 예약 결과 정리해 줘" 라고 하면 됩니다. Claude 는 이 순서로 읽습니다.

1. `{ "action": "schedules" }` 로 예약 목록과 마지막 상태, 연속 실패 횟수를 봅니다.
2. `{ "action": "history", "since": "<어제 22:00>", "limit": 50 }` 로 밤새 실행 요약을
   받습니다. 목록에는 결과 본문이 실리지 않습니다. 30건 x 24,000자를 그대로 실으면
   대화 컨텍스트를 밀어내기 때문입니다.
3. 실패한 건은 `{ "action": "history", "runId": "..." }` 로 하나씩 열어 오류와 스크린샷
   경로를 봅니다.
4. 성공한 건 중 수치가 필요한 것만 `runId` 로 열어 표로 만듭니다.
5. 반복 실패가 작업 자체의 결함이면 `save` 로 고치고 `schedule` 을 다시 겁니다.

상태는 여덟 가지입니다.

| 상태                 | 뜻                                                |
| -------------------- | ------------------------------------------------- |
| `success`            | 끝까지 돌았습니다                                 |
| `stopped`            | `stopIf` 로 정상 조기 종료 (새 글 없음 등)        |
| `failed`             | 어느 단계가 실패했습니다                          |
| `timeout`            | 100초 상한을 넘겼습니다                           |
| `interrupted`        | 실행 도중 크롬이나 확장이 멈췄습니다              |
| `skipped_queue`      | 앞선 실행이 밀려 10분을 넘겨 아예 돌지 않았습니다 |
| `login_required`     | `loginCheck` 가 로그인 화면을 잡았습니다          |
| `user_took_over_tab` | 실행 중 여러분이 그 탭을 열어 실행을 양보했습니다 |

## 사용자 화면을 방해하지 않습니다

예약 실행은 다음을 지킵니다.

- 탭은 **배경**에 조용히 열립니다. 탭을 앞으로 가져오거나 창을 포커스하지 않습니다.
  전역 무간섭 토글이 꺼져 있어도 예약 실행만은 항상 무간섭입니다.
- 실행 중에는 MCP 탭 그룹 라벨이 `예약: <이름>` 으로 바뀝니다. 무엇이 도는지 알 수 있는
  표시입니다. 끝나면 `MCP` 로 돌아갑니다.
- 예약 실행이 만든 탭은 그 실행이 끝나면 닫힙니다. 아침에 탭 스무 개가 쌓이지 않습니다.
- 그 탭을 여러분이 눌러서 보고 있으면 실행이 스스로 멈추고(`user_took_over_tab`) 탭은
  **닫지 않고** 그대로 둡니다. 보고 있는 화면을 도구가 조작하거나 닫는 일이 없습니다.
- 여러분이 보던 다른 탭은 어떤 경우에도 대상이 되지 않습니다.

## 제한 사항

| 항목             | 값                                                 |
| ---------------- | -------------------------------------------------- |
| 예약 개수        | 20개                                               |
| 최소 간격        | `every` 최소 15분, `daily` 시각 간 5분             |
| 한 실행          | 도구 호출 100회, 100초 (전체 120초)                |
| 큐 대기          | 10분을 넘기면 `skipped_queue` 로 기록하고 버립니다 |
| 이력 보관        | shortcut 당 100건, 전체 1,000건, 전체 3MiB         |
| 이력의 결과 크기 | 항목당 8,000자, 전체 24,000자 (`report` 는 256KiB) |
| 알림             | 연속 실패 1회째와 3회째만                          |

그리고 하지 않는 것들이 있습니다. 이유가 있어서 안 하는 것이니 요청해도 같은 답이
돌아옵니다.

- **비밀번호·토큰 저장**: 저장이 곧 평문 노출입니다. 1단계 참조.
- **크롬 밖 실행**: 쿠키·확장·보호 규칙이 전부 프로필 안에 있습니다.
- **예약 병렬 실행**: 창 하나에 탭이 동시에 열리는 것이 보이고, 탭 그룹과 다운로드
  폴더가 경합합니다. 예약은 한 번에 하나씩 돕니다.
- **놓친 실행 전부 따라잡기**: 8시간 꺼져 있었다면 8번이 아니라 **1번**만 돕니다.
  같은 결과를 여덟 번 받아 봐야 아침 크롬만 점유합니다.
- **실패 시 자동 재시도**: 로그인 만료나 사이트 변경은 재시도로 풀리지 않습니다.
  다음 주기가 곧 재시도입니다.
- **크롬이 꺼져 있으면 안 돕니다.** 다음에 크롬을 켤 때 지난 예약이 한 번 따라잡습니다.
